## Security focus areas

### Cloud security
Identity and access control, secure baseline configuration, network boundaries inside the cloud, and the logging needed to know when something changed. Most cloud incidents start with a permissive identity or a public endpoint, so that is where the review starts.

### Network security
Firewall and VPN configuration, segmentation, and reading the traffic to understand what each rule is really permitting. Security rules age badly — the job is removing the ones that no longer earn their place.

### Operating system hardening
Windows and Linux hardening: patching, service exposure, privilege management and configuration baseline drift. Uptime is part of the same job, because an unavailable system is a security problem too.

### OSINT and threat intelligence
Open-source intelligence collection for recon and investigations, and turning raw findings into something that supports a decision. A tool that produces 10,000 rows is not intelligence; the value is in the enrichment and the triage.

## How I work

1. **Scope** — agree what is in and out, and what "done" means.
2. **Map** — inventory the assets, exposures and dependencies before touching anything.
3. **Prioritise** — rank by real risk and business impact, not by scanner severity score.
4. **Fix** — implement the change, then verify it in place.
5. **Document** — leave behind the reasoning, so the next person can maintain it.
